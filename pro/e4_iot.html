Contexte et Enjeux

Surveillance critique de **4 baies serveurs**. L'objectif est de prévenir les pannes matérielles liées à des conditions environnementales hors normes (température excessive, humidité).

Architecture du Système

1. Couche IoT (ESP32)

Acquisition via capteurs **AHT20** (I2C) et synchronisation temporelle **NTP**.

C++ Embedded I2C Pins 21/22 WiFi 2.4GHz

2. Couche Serveur (Raspberry Pi)

Concentrateur de données sous **Linux Debian** (Raspberry Pi 400).

Apache2 PHP 8.2 MariaDB (Port 13306)

3. Couche Supervision (Dashboard)

Interface Web responsive pour le monitoring en temps réel.

Chart.js Tailwind CSS PDO MySQL

Modélisation Merise

MCD (Modèle Conceptuel)

BAIE (1,1) --- [Contient] --- (1,1) CAPTEUR
CAPTEUR (0,n) --- [Génère] --- (1,1) MESURE

MLD (Modèle Logique)

baies (id_baie, nom_baie)
capteurs (id_capteur, reference, #id_baie)
mesures (id, temperature, humidite, date_mesure, #id_capteur)

Cybersécurité Appliquée

Contrôle d'Accès Web

Mise en œuvre de **.htaccess** (AuthType Basic) et **.htpasswd** pour protéger le Dashboard. Utilisation de l'algorithme **Bcrypt** pour le stockage des identifiants.

Sécurisation Réseau

Firewall **UFW** configuré sur le Raspberry Pi pour n'autoriser que le réseau local SNIR (172.17.0.0/16) sur les ports 22, 80 et 13306.
